# Fix: GlobalExceptionMiddleware and ResponseWrapperMiddleware Conflict

## Problem

When both middlewares are active, global exception returns HTTP 500 but with an **empty body**.

## Root Cause

Middleware registration order in `Program.cs` (lines 71-72):

```csharp
app.UseMiddleware<GlobalExceptionMiddleware>();  // outer
app.UseMiddleware<ResponseWrapperMiddleware>();   // inner
```

Pipeline: `Request → GlobalExceptionMiddleware → ResponseWrapperMiddleware → Controllers`

When a controller throws an exception:

1. `ResponseWrapperMiddleware` replaces `context.Response.Body` with a `MemoryStream` (line 20), then calls `_next(context)` (line 22)
2. Exception propagates out of `ResponseWrapperMiddleware` (no try-catch) **back to** `GlobalExceptionMiddleware`
3. `GlobalExceptionMiddleware` catches the exception, writes error JSON to `context.Response.Body` — which is **still the `MemoryStream`** from step 1
4. `ResponseWrapperMiddleware`'s post-processing (lines 24-108) **never executes** because the exception already exited its scope

Result: error data is trapped in the `MemoryStream`, never copied to the real response stream → **empty body**.

## Fix

Swap the two middleware registrations in `Program.cs` so `ResponseWrapperMiddleware` is **outer** and `GlobalExceptionMiddleware` is **inner**:

```csharp
app.UseMiddleware<ResponseWrapperMiddleware>();
app.UseMiddleware<GlobalExceptionMiddleware>();
```

New pipeline: `Request → ResponseWrapperMiddleware → GlobalExceptionMiddleware → Controllers`

When an exception occurs now:

1. `ResponseWrapperMiddleware` replaces body with `MemoryStream`, calls `_next`
2. `GlobalExceptionMiddleware` catches exception, writes error JSON to `MemoryStream`, **returns normally**
3. `ResponseWrapperMiddleware`'s `_next` completes (no exception), post-processing runs
4. Status >= 400 branch copies `MemoryStream` content to original stream → **body is delivered**
