# Plan: ResponseWrapperMiddleware 跳过静态资源路径

## Problem
`ResponseWrapperMiddleware` 拦截了 `/statics/**` 下的静态文件请求，将二进制内容（图片等）包装为 JSON，导致响应长度和 Content-Type 被篡改。

## Solution
在 `InvokeAsync` 方法开头添加路径判断，当请求路径以 `/statics/` 开头时，直接调用 `_next(context)` 跳过包装逻辑。

## File to Modify
- `Middlewares/ResponseWrapperMiddleware.cs` — 在 `InvokeAsync` 方法第 17 行后（`_next` 调用前）插入跳过逻辑

## Change
```csharp
// 在 await _next(context); 之前添加:
if (context.Request.Path.StartsWithSegments("/statics"))
{
    await _next(context);
    return;
}
```

## Verification
1. `dotnet build` 确认编译通过
2. 启动服务后访问 `/statics/avatars/xxx.png`，确认返回原始图片（Content-Type 为 image/*，响应体为二进制）
3. 访问 `/account/login` 等 API，确认仍被包装为 `ApiResponse` 格式
